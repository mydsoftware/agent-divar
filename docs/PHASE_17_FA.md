# فاز ۱۷ — صف بازبینی اطلاعات تماس و پیش‌نویس چت

## رفتار

1. پیمایشگر، آگهی منطبق را در مرورگر قابل مشاهده باز می‌کند.
2. فقط شماره‌ای که در متن قابل مشاهده صفحه یا پیوند قابل مشاهده `tel:` وجود دارد خوانده می‌شود. کاربر باید در صورت نیاز، نمایش شماره را خودش در رابط دیوار انجام داده باشد.
3. وضعیت وجود کادر چت قابل مشاهده تشخیص داده می‌شود.
4. پس از ذخیره آگهی منطبق در CRM، اطلاعات حداقلی در صف بازبینی محلی ذخیره می‌شود؛ تکرار آگهی رکورد تکراری ایجاد نمی‌کند.
5. متن الگوی کمپین به‌عنوان پیش‌نویس ذخیره می‌شود و در تب «بازبینی تماس و چت» قابل مشاهده و کپی است.
6. کاربر می‌تواند پرونده را برای استفاده دستی تأیید یا در فهرست «عدم تماس» قرار دهد.

## مرزهای عملیاتی

- هیچ دکمه‌ای برای آشکارسازی شماره کلیک نمی‌شود.
- داده‌های پنهان DOM، درخواست‌های شبکه، API خصوصی یا اطلاعات خارج از صفحه قابل مشاهده خوانده نمی‌شوند.
- هیچ تماس تلفنی یا پیام چتی ارسال نمی‌شود؛ حتی اگر کادر چت فعال باشد.
- دکمه ارسال پیام هرگز پیدا یا کلیک نمی‌شود.
- کپچا/محدودیت در صورت مشاهده باعث توقف پیمایش می‌شود.
- شماره تماس در گزارش‌ها و رویدادهای عیب‌یابی ثبت نمی‌شود.
- اطلاعات در پایگاه داده محلی باقی می‌ماند؛ وضعیت اولیه هر پرونده «نیازمند بررسی انسانی» است.
- گزینه «عدم تماس» مانع ثبت/به‌روزرسانی خودکار بعدی برای همان آگهی می‌شود.

## مهاجرت و آزمون

- نسخه پایگاه داده به ۸ ارتقا می‌یابد؛ جدول `contact_review_queue` با کلید یکتای `lead_id` افزوده می‌شود.
- آزمون‌های نرمال‌سازی شماره، خواندن متن قابل مشاهده، تشخیص چت، پرکردن پیش‌نویس بدون ارسال، جلوگیری از رکورد تکراری و فهرست عدم تماس در `tests/test_contact_chat_assistant.py` قرار دارند.
- اجرای همه آزمون‌ها:

```bash
python -m unittest discover -s tests -v
```

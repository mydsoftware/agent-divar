# Agent Divar

سامانه دسکتاپ ویندوزی مدیریت سرنخ‌ها و کمپین‌های کسب‌وکار با رابط فارسی.

## وضعیت فعلی

این مخزن در حال توسعه مرحله‌ای است. نسخه فعلی شامل تعریف کمپین، اجرای مرورگر زنده، پیمایش خودکار و قابل مشاهده آگهی‌ها، ثبت دستی سرنخ‌های مجاز، مدیریت وضعیت پیگیری و خروجی Excel است.

**توجه:** پیمایش خودکار فقط آگهی‌های قابل مشاهده را در مرورگر باز و به صفحه نتایج بازمی‌گرداند. استخراج متن/اطلاعات تماس، ثبت خودکار در CRM و اعمال واقعی فیلتر تاریخ انتشار هنوز فعال نیستند.

## اجرا در ویندوز

1. Python 3.10 یا جدیدتر را نصب کنید.
2. در پوشه پروژه اجرا کنید:

   ```powershell
   python -m pip install -r requirements.txt
   python -m playwright install chromium
   python app.py
   ```

   یا فایل `run_windows.bat` را اجرا کنید.

## قابلیت‌های نسخه پایه

- رابط گرافیکی فارسی با Tkinter
- تعریف و ویرایش چند کمپین
- اجرای زنده و قابل‌مشاهده Microsoft Edge یا Chromium با Playwright؛ پروفایل ورود محلی در پوشه data/browser-profile حفظ می‌شود\n- پیمایش خودکار محدود آگهی‌های قابل مشاهده: بازکردن صفحه آگهی و بازگشت به نتایج، با توقف در صورت مشاهده کپچا/محدودیت\n- عدم استخراج شماره تماس، پیام‌ها یا اطلاعات شخصی؛ ثبت سرنخ همچنان پس از بررسی انسانی انجام می‌شود
- مدیریت چرخه عمر مرورگر، شامل اجرای مجدد و دکمه مستقل بستن مرورگر
- جست‌وجو بر اساس کد شهر و کلمات کلیدی
- تنظیم بازه تاریخ انتشار آگهی برای کمپین
- ثبت دستی اطلاعات آگهی و راه تماس عمومی/مجاز
- ثبت وضعیت رضایت و مرحله فروش
- جلوگیری از ثبت لینک تکراری
- ذخیره‌سازی محلی با SQLite
- خروجی Excel راست‌به‌چپ با لینک قابل کلیک

## حریم خصوصی و قوانین پلتفرم

این پروژه برای استخراج انبوه اطلاعات شخصی، دور زدن محدودیت‌های پلتفرم یا ارسال پیام تبلیغاتی سرد طراحی نمی‌شود. اتصال به دیوار باید از مسیرهای رسمی و مجاز و مطابق مستندات و مجوزهای لازم پیاده‌سازی شود. پیام‌رسانی فقط در سناریوهای مجاز و با رضایت یا درخواست لازم انجام می‌شود. عملیات حساس باید قابل مشاهده، قابل توقف و ثبت‌شده باشد.

- https://divar-ir.github.io/kenar-docs/chat/users_conversations/
- https://divar-ir.github.io/kenar-docs/oauth/get_user/

## تحلیل آگهی و تطبیق با نیاز مشتری

ماژول `listing_analyzer.py` امتیاز تطبیق آگهی با معیارهای مشتری را به‌صورت قطعی و توضیح‌پذیر محاسبه می‌کند. معیارهای قابل‌مقایسه شامل بودجه، متراژ، تعداد اتاق، محدوده و امکانات هستند. داده‌های ناموجود از امتیازدهی حذف می‌شوند و اگر هیچ داده مشترکی وجود نداشته باشد، نتیجه «اطلاعات ناکافی» است؛ هیچ قیمت یا ویژگی مفقودی حدس زده نمی‌شود. مقایسه قیمت هر متر نیز فقط وقتی انجام می‌شود که قیمت و متراژ هر دو آگهی معتبر باشند.

اجرای تست‌ها:

```bash
python -m unittest discover -s tests -v
```

## پشتیبان‌گیری، بازیابی و نصب ویندوز (فاز ۹)

### نصب
1. Python 3.11 را نصب کنید.
2. مخزن را دریافت و از حالت فشرده خارج کنید.
3. روی فایل `install_windows.ps1` راست‌کلیک و اجرای PowerShell را انتخاب کنید؛ در صورت نیاز سیاست اجرای اسکریپت را فقط برای همان نشست با دستور `Set-ExecutionPolicy -Scope Process Bypass` تغییر دهید.
4. نصب‌کننده محیط مجازی مستقل، وابستگی‌ها و Chromium موردنیاز Playwright را نصب می‌کند و میانبر دسکتاپ می‌سازد.
5. برای اجرای برنامه از میانبر دسکتاپ یا `run_windows.bat` استفاده کنید.

### پشتیبان‌گیری و بازیابی
- از تب «پشتیبان‌گیری و بازیابی» یک فایل ZIP شامل snapshot سازگار SQLite و همه تصاویر/مدارک محلی بسازید.
- پیش از بازیابی، ساختار آرشیو، نسخه قالب و اثرانگشت SHA-256 فایل‌ها بررسی می‌شود.
- مسیرهای ناامن و آرشیو دستکاری‌شده رد می‌شوند.
- بازیابی، پایگاه داده و پوشه رسانه را جایگزین می‌کند؛ قبل از آن برنامه را ببندید.
- فایل پشتیبان را روی حافظه یا محل جداگانه نگهداری کنید؛ نسخه پشتیبان در همان رایانه به‌تنهایی در برابر خرابی دیسک کافی نیست.

تست‌های این بخش در `tests/test_backup_manager.py` قرار دارند.

## نسخه اجرایی مستقل ویندوز (فاز ۱۱)
- ساخت نسخه پوشه‌ای مستقل با PyInstaller و Python 3.11
- بسته‌بندی وابستگی Playwright و مرورگر Chromium
- ذخیره پایگاه‌داده، تنظیمات، تصاویر و پروفایل مرورگر در مسیر مستقل کاربر: `%LOCALAPPDATA%\\AgentDivar\\data`
- اجرای runner مرورگر از همان فایل EXE؛ بدون نیاز به فایل پایتون جداگانه
- آزمون دود بسته ساخته‌شده با گزینه `--self-test`
- راهنمای ساخت در `docs/WINDOWS_RELEASE_FA.md`

برای ساخت در ویندوز، PowerShell را در ریشه پروژه باز و `build_windows.ps1` را اجرا کنید. خروجی کامل در `dist/AgentDivar` قرار می‌گیرد. تمام پوشه را توزیع کنید؛ فایل EXE به‌تنهایی کافی نیست.

گردش‌کار GitHub Actions نیز پس از هر تغییر مرتبط در PR، بسته اجرایی ویندوز را می‌سازد، آزمون دود را اجرا و Artifact را برای ۱۴ روز نگه می‌دارد.


## مهاجرت امن اطلاعات نسخه قدیمی
در اولین اجرای نسخه بسته‌بندی‌شده، اگر پوشه `data` کنار فایل اجرایی وجود داشته باشد، اطلاعات آن به مسیر `%LOCALAPPDATA%\\AgentDivar\\data` کپی می‌شوند. پایگاه‌داده با SQLite backup API و کنترل سلامت منتقل می‌شود؛ تنظیمات، وضعیت مرورگر، پروفایل مرورگر و رسانه‌ها نیز کپی می‌شوند. داده مقصد بازنویسی نمی‌شود و داده قدیمی حذف نخواهد شد. مهاجرت در اجراهای بعدی تکرارپذیر و غیرمخرب است.

## ثبت اطلاعات تماس قابل مشاهده و دستیار پیش‌نویس چت (فاز ۱۷)

- شماره موبایل فقط از متن قابل مشاهده صفحه آگهی یا پیوند قابل مشاهده `tel:` خوانده می‌شود؛ نمایش شماره باید قبلاً در رابط عادی دیوار انجام شده باشد.
- هیچ دکمه‌ای برای آشکارسازی شماره کلیک نمی‌شود و داده پنهان DOM یا درخواست‌های شبکه خوانده نمی‌شود.
- اطلاعات در صف بازبینی محلی و با وضعیت اولیه «نیازمند بررسی انسانی» ذخیره می‌شود؛ تکرار آگهی رکورد تازه نمی‌سازد.
- وضعیت «عدم تماس» مانع به‌روزرسانی خودکار همان پرونده می‌شود.
- اگر کادر نوشتن چت یکتا و قابل مشاهده باشد، متن پیش‌نویس در آن قرار می‌گیرد؛ هیچ دکمه ارسال پیدا یا کلیک نمی‌شود.
- ارسال پیام، تماس تلفنی، دور زدن محدودیت یا ارسال انبوه در این فاز وجود ندارد.
- شماره تماس در گزارش‌ها و رویدادهای عیب‌یابی ثبت نمی‌شود.
- مهاجرت SQLite به نسخه ۸ افزایشی است و جدول صف بازبینی را بدون حذف داده‌های قبلی می‌سازد.

تست‌های این فاز در `tests/test_contact_chat_assistant.py` قرار دارند.
